## Context

仓库最初只有一个要求 Python 3.13 的占位入口。动机见 `proposal.md`，新增的可观察行为见 `specs/uv-index-management/spec.md`。

uv 不同于 npm 的单 registry 模型：它会从系统、用户、项目、环境变量和命令行层级发现配置，支持多个命名索引，并且同一目录中的 `uv.toml` 优先于 `pyproject.toml` 的 `[tool.uv]`。较新的 uv 版本还会拒绝包含多个结构化默认索引的配置。因此，实现必须复现 nrm 的命令体验，同时不能把 uv 配置当成一个不透明的 registry 字符串。

支持 Python 3.9 意味着不能使用标准库 `tomllib` 读取器，而保留现有 TOML 注释和未知字段又是产品要求。

## Goals / Non-Goals

**目标：**

- 让命令名、位置参数、常用选项、输出层次和交互式选择对 nrm 用户保持熟悉。
- 将可复用的索引目录与实际生效的 uv 配置分离。
- 让用户级和项目级配置编辑保持窄范围、原子性、注释保留且可解释。
- 解析足够完整的 uv 配置优先级，使当前目录中的 `current` 和 `ls` 输出真实可信。
- 在 Linux、macOS 和 Windows 上为 Python 3.9+ 提供确定且可测试的核心行为。

**非目标：**

- 重新实现 uv 的解析器、凭据存储或发布流程。
- 将 uv 的软件包级来源视作 npm scope 的等价物。
- 修改系统级 uv 配置。
- 自动改写带有额外语义且不受管理的结构化默认索引。
- 保证 uim 未修改的 TOML 节点之外仍逐字节保持原格式。

## Decisions

### 使用小型分层 Python CLI 架构

将应用划分为 CLI 适配器、目录服务、生效配置解析器、TOML 配置编辑器和端点探测器。CLI 命令负责编排这些服务，但不直接解析或重写 TOML。

这样可以为单元测试注入文件系统和网络行为，并防止各命令的实现逐渐分叉。曾考虑单文件脚本，但配置优先级、跨平台路径和事务式编辑都是相互独立的复杂问题，因此未采用。

### 通过软件包元数据暴露 `uim`，并支持 Python 3.9+

使用可导入的软件包和 console-script 入口替代顶层占位 `main.py`。采用成熟且兼容 Python 3.9 的命令框架，显式定义命令名和选项；优先选择 Click，因为其命令模型贴近 nrm 子命令，且不依赖较新的类型语法。

软件包版本是 `uim --version` 的唯一来源。为减少兼容分支，不支持早于 Python 3.9 的版本；继续维持 3.13 最低版本会给迁移型工具带来不必要的采用阻力，因此未采用。

### 内置条目保存在代码中，自定义条目保存在 uim 配置中

内置索引定义是不可变的软件包数据。只把自定义条目持久化到符合平台规范的用户级 uim TOML 文件中。加载时先验证自定义名称不会遮蔽内置条目，再合并两者。

不单独保存 `current` 值。当前索引从实际生效的 uv 配置中推导，因此手动编辑和项目覆盖不会让 uim 的显示过期。

### 使用 uv 的默认索引设置表示所选镜像

通常将镜像切换写为 uv 的标量 `default-index` 设置：在 `uv.toml` 顶层写入，或写入 `pyproject.toml` 的 `[tool.uv]`。这直接对应 nrm 的切换操作，同时保留补充的 `[[index]]` 条目。替换旧版标量 `index-url` 时，删除已被取代的标量，避免向 uv 提供互相矛盾的默认值。

对于用户级 `uv.toml` 中只含 `name`、`url` 和 `default = true` 的简单命名默认索引，原地更新名称和 URL，保留 uv 的命名索引结构。项目级命名默认索引可能被 `tool.uv.sources` 引用，因此不自动改写。

曾考虑总是新增带 `default = true` 的命名 `[[index]]` 条目，但它可能与已有结构化默认项或名称冲突，并让简单 URL 切换意外进入命名索引语义，因此未采用。

写入前检测所有标记为默认值的结构化 `[[index]]` 条目。若条目包含认证、显式选择或其他不受管理的语义，或目标名称会重复，则给出可执行的冲突错误。初始安全路径绝不静默丢弃这些属性。

### 按作用域和 uv 发现行为解析写入目标

默认用户作用域按照 uv 的 XDG 和 Windows 约定定位用户配置目录，并在需要时创建父目录。

对于 `--local`，从当前目录向适用的项目根目录查找：

1. 使用最近的适用且已存在的 `uv.toml`。
2. 否则使用最近的适用 `pyproject.toml` 并编辑 `[tool.uv]`。
3. 若两者均不存在，则在交互式终端中确认后于当前目录创建 `uv.toml`；自动化场景必须提供显式的非交互确认选项。

不能仅因为存在 `pyproject.toml` 就创建同目录的 `uv.toml`，否则 uv 会忽略该文件中的 `[tool.uv]` 表。

### 保留 TOML 结构并原子替换文件

使用 `tomlkit` 兼顾 Python 3.9 的 TOML 解析与注释保留。只编辑选定的默认设置以及被直接取代的旧版标量。渲染后先验证文档，再写入目标目录中的临时文件；刷新数据，尽可能保留已有权限，最后原子替换目标文件。

TOML 格式错误、不支持的结构、写入失败或替换失败都会中止，并且不会有意修改原文件。手写 TOML 序列化，以及 `tomllib` 配合另一写入器的方案，都无法稳定满足注释保留要求，因此未采用。

### 将生效配置建模为值与来源

解析器同时返回生效 URL 及其来源：环境变量、本地 `uv.toml`、本地 `pyproject.toml`、用户 `uv.toml`、系统配置或 uv 隐式的 PyPI 默认值。URL 只在匹配时规范化（例如处理末尾斜杠），显示和写入仍保留配置值。

按照 uv 的文档应用优先级，包括现代默认索引环境变量及受支持的旧别名。对本地和用户 TOML 的数组、标量只解析到识别实际默认索引所需的程度。`current --verbose` 显示来源和遮蔽关系，从而解释为何全局 `use` 可能被项目或环境变量覆盖。

无法预测后续 uv 调用携带的命令行选项，因此它们不属于 `uim current` 的生效状态定义。

### 使用标准库 HTTPS 探测和有界并发

绝不对配置的 `/simple` 根索引发出 `GET` 或下载它：公共镜像的项目列表可能达到数十 MB，生成列表可能耗时，且通用根请求容易触发限流。应在规范化的 Simple Repository URL 下派生轻量的 `pip/` 项目端点，并发送真实的 `uim/<version>` User-Agent。

优先使用 `HEAD` 探测轻量端点，使成功检查不传输响应体。仅当端点以 HTTP 405 或 501 明确拒绝 `HEAD` 时，才对同一端点使用带 `Range: bytes=0-0` 的 `GET`，并在客户端最多读取一个字节。保持 TLS 验证，遵循标准库重定向，设置有界超时，并限制并发工作线程数量。使用单调时钟测量完整尝试的耗时，所有探测结束后按确定的目录顺序分别报告结果。

标准库足以完成小型健康检查，可避免额外的运行时 HTTP 依赖。根索引 GET 和下载吞吐基准会施加不必要的负载，并让结果主要受项目列表大小、软件包选择、缓存、CDN 行为和镜像同步影响，而不是基本可达性，因此未采用。

### 将认证交给 uv，并使用平台浏览器集成

拒绝目录 URL 中嵌入的凭据，并从错误中脱敏用户信息。uim 不持有秘密。未来的 `login` 命令可在版本检测后委托给兼容的 `uv auth login`。

`home` 使用平台浏览器集成；若指定浏览器参数，只解析命名浏览器或明确的可执行文件，绝不调用 shell。

## Risks / Trade-offs

- **[uv 配置语义演进]** → 隔离优先级和受支持键的处理，针对声明的 uv 兼容范围测试，并为旧键增加夹具。
- **[全局切换在受覆盖项目中看似无效]** → 报告目标作用域写入成功，同时在更高优先级的本地或环境值仍生效时发出警告。
- **[用户的结构化默认索引无法安全转换]** → 带来源和修复指引拒绝写入，绝不静默展平。
- **[保留注释的库仍可能规范化被触及的 TOML]** → 将修改限制在最少节点，并测试代表性格式夹具。
- **[并发测试让小型私有索引过载]** → 限制工作线程，不 GET 根索引，并用可配置超时把回退响应限制为一个字节。
- **[内置镜像端点变化]** → 集中维护，在发布检查中验证，并允许用户以不同名称添加自定义替代项，而不让内置项可变。
- **[Python 分发名与可执行名可用性不同]** → 将 `uim` 作为必需的可执行名；首次发布前验证分发名可用性，必要时使用 `uv-index-manager` 作为分发名。

## Migration Plan

1. 将占位项目转换为暴露 `uim` console 命令的软件包，并把 `requires-python` 降至 3.9。
2. 先增加目录和只读命令，使用户无需修改即可检查现有 uv 配置。
3. 增加事务式用户级和项目级切换，并以夹具验证兼容性。
4. 增加主页和并发测试命令、文档及跨平台 CI。
5. 发布首个 1.0 前版本；回滚只需卸载 uim，因为它不需要守护进程或 shell hook，所有 uv 变更都是普通 TOML 设置。

每次修改配置前，在内存中保留足够的原始内容，保证失败时文件不变。仅安装或升级 uim 不会自动迁移用户配置。
